11. ビルドとリリース

バージョン管理、ビルドの設定、CI、スモークテスト、リリースの手順。

11.2 バージョン管理

  • 版の番号はルートの VERSION（メジャー.マイナー.パッチ）だけに書く
  • versionName はこの値、versionCode は メジャー × 10000 + マイナー × 100 + パッチ（2.4.2 → 20402）
  • 不具合の修正はパッチ、機能の追加はマイナーを上げる
  • CHANGELOG.md の先頭に ## <版> の節を書く。リリースノートとアプリ内のお知らせに使う

11.3 署名

リリース用の署名鍵の情報は、リポジトリの外の ~/.config/spotfy/keystore.properties（環境変数 SPOTFY_KEYSTORE_PROPERTIES で変えられる）から読みます。CI には鍵が無いので、デバッグ鍵で署名します。

11.4 ブランチと CI

  • 作業ブランチから main への PR を作り、CI がすべて通ったらマージする。main へ直接 push しない
  • CI（GitHub Actions）は PR と main への push のたびに動く
ジョブ内容
buildbridge.js・polyfill.js・スクリプトの構文チェック、リリース設定でのビルド、APK の保存
smoke（Android 15）google_apis のエミュレーター（新しい WebView）でスモークテスト
smoke（Android 8）素のエミュレーター（WebView なし）でスモークテスト

11.5 スモークテスト（scripts/smoke-test.sh）

  • 初回の起動でログイン画面が出る
  • 通信できないときに「Spotify に接続できません」が出て、つながると自動でログイン画面に戻る（日本語・英語のどちらの表示でも判定する）
  • WebView が使えない端末で、落ちずに更新の案内が出る
  • 「応答なし」のダイアログが出たら自動で「待機」を押す
  • 環境変数：SMOKE_AVD・SMOKE_AVD_OLD（使う AVD）、SMOKE_SERIAL・SMOKE_CASES（起動済みのエミュレーターを使う）

11.6 リリースの手順（scripts/release.sh）

  1. VERSION と CHANGELOG.md を更新して PR → CI → main にマージ
  2. main の最新で scripts/release.sh を実行する
  3. スクリプトは次のどれかなら止まる：同じ版のタグがある、コミットしていない変更がある、main の最新でない、CHANGELOG に節がない
  4. スモークテストを実行する（急ぐときは SKIP_SMOKE=1）
  5. 署名付きでビルドし、build/spotfy-<版>.apk を作る
  6. v<版> のタグを付けて push し、GitHub Releases に APK とその版の節を上げる
  7. 利用者の端末では、アプリ内アップデートで新しい版のお知らせが出る
