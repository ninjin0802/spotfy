12. セキュリティと制約

守っていること、既知の制約、運用上のリスク。

12.1 守っていること

対象対策
ログインSpotify 公式のログインページを使う。アプリはパスワードを扱わない
ページとの通信AndroidBridge は open.spotify.com のメインフレームにだけ注入し、届いたメッセージの送信元とメインフレームかを確認する
スクリプトの注入polyfill.js・bridge.js は open.spotify.com にだけ入れる
独自スキームspotify:・intent: などの独自スキームへの移動は無視する（ほかのアプリを勝手に開かない）
Connect の送り直しSpotify のドメインの決まったパスと方法だけ。Cookie・User-Agent は付けない。リダイレクト先に Cookie を渡さない
共有アプリから共有できるのは https://open.spotify.com/ のリンクだけ
アップデートhttps だけ、同じ署名の APK でしか上書きできない。https 以外への転送は拒否
ログトークン・Cookie は記録しない。長さと文字を制限する。ログアウトで消す
保存曲を端末に保存しない。中継サーバーを持たない
Activity・Service外部に公開するのは起動用の MainActivity だけ。Receiver・Service・FileProvider は非公開

12.2 既知の制約

  • Web Player の内部の部品・GraphQL のハッシュに依存するため、Spotify の更新で動かなくなることがある
  • Premium・公式アプリ専用の機能（ロスレス・Jam・ダウンロード・最高音質）は使えない
  • Spotify の公開 Web API はこのアプリのトークンでは 429 になるため使えない（再生回数の統計なども作れない）
  • 準備が終わる前に再生ボタンを押すと、反応しないことがある（bridge.error toggle）
  • 起動には Web Player の読み込み分の時間がかかる（約 2 秒）

12.3 運用上のリスク

広告の処理は Spotify の利用規約に反する可能性があり、アカウントに影響する場合があります。spotfy は Spotify AB とは関係のない非公式のアプリです。「Spotify」は Spotify AB の商標です。
  • 目立つと削除の要請を受ける可能性があるため、特設サイトなどで広く宣伝しない方針
  • GitHub API の回数制限に達したときは、リリースページから更新を確かめる（8 章）
