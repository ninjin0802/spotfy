10. 診断とログ

Spotify の更新で壊れたときに原因を追うための仕組み。

10.1 デバッグログ

項目内容
形式yyyy-MM-dd HH:mm:ss.SSS イベント 詳細（1 行 1 件）
上限最新 800 行。古いものから消える
保存SharedPreferences（settings の debug.log）。少し待ってからまとめて保存
logcatタグ spotfy-debug でも出す
消すときログアウトしたとき
安全イベント名は英数字と ._- だけ（64 文字まで）、詳細は改行を消して 160 文字まで。通信は URL の主要部分だけ記録する

取り出し方

adb shell am start -n com.ninjin.spotifyweb/.MainActivity --ez dumpDebugLog true
adb logcat -s spotfy-debug

アプリの設定 →「デバッグログを共有」からも送れます。

主なイベント

イベント意味
bridge.health健康診断の結果（ok か、足りない機能の名前）
bridge.error / bridge.timeoutメソッドの失敗・時間切れ
ad.manager.disabled / enabled広告マネージャーの停止・復帰
ad.detected / ad.mute.* / ad.speed.applied / ad.skip.* / ad.state.ended広告の処理（7 章）
connect.active再生中の機器が変わった（種類・音量）
net / net.adpath通信の記録（広告関係の通信は net.adpath）
page.error / page.renderer_goneページの読み込みの失敗、WebView のプロセスの停止（crash / killed）
update.*アップデートの失敗（8 章）

10.2 健康診断

Web Player の準備ができてから 5 秒後に、使っている部品がそろっているかを確かめ、足りないものを bhealth で知らせます。足りないものがあれば、設定のいちばん上に「⚠ 一部の機能が使えません」と出ます。

機能確かめること
データの取得（ホーム・検索・ライブラリ）GraphQL ローダーがある
再生の操作PlayerAPI に getState・skipToNext・seekTo がある
音量・広告の早送り・クロスフェードstreamer の音声要素にたどり着ける
音質の切り替えsetMediaPlaybackQuality がある
ギャップレス再生先読みの関数がある
広告の停止AdManagers.audio がある
ログイン情報AuthorizationAPI.getState がある

10.3 エラーの表示

場面表示
通信できない「Spotify に接続できません」の画面。再試行ボタン、つながったら自動で開き直す
WebView が無い・古いWebViewMissingActivity で「Android System WebView が必要です」と案内する（落ちない）
WebView のプロセスが落ちたActivity を作り直す
データの読み込みに失敗各画面で「読み込めませんでした」などを出す
