5. ブリッジ

アプリ（Kotlin）とページ（JavaScript）の間の通信の仕組み、メッセージの形式、呼べるメソッド。

5.1 通信の経路

向き手段備考
ページ → アプリAndroidBridge.postMessage(JSON)addWebMessageListener で open.spotify.com のメインフレームにだけ注入。送信元のオリジンとメインフレームかを確認する
アプリ → ページ（返事）JavaScriptReplyProxy.postMessage設定（settings）と Connect の送り直しの結果（relay）
アプリ → ページ（呼び出し）evaluateJavascript("__mb.call(id, method, args)")結果は bres で非同期に返る

5.2 ページから届くメッセージ

type中身受け取り先
breadyWeb Player の準備ができたBridge（ready = true）
bresid, ok, value | errorBridge（待っている呼び出しを再開）
bstate再生状態（下の表）Bridge（player）
bhealthmissing：使えない機能の名前の配列Bridge（missing）・デバッグログ
meta曲名・アーティスト・アルバム・画像・再生中か・位置・長さMediaControls
playing再生中かどうかPlaybackService の起動・停止
debugevent, detailDebugLog
hello / setting設定の取得・保存（向き・バックグラウンド・広告・webdebug）MainActivity
relayConnect の通信の送り直しの依頼ConnectRelay
share / outputSwitch / hideKeyboard共有シート・出力の切り替え・キーボードを閉じるMainActivity

5.3 再生状態（bstate の value）

キー型意味
hasboolean再生中の項目があるか
uri / title / artist / album / imagestring曲の情報（画像は https の URL に直す）
artistUri / contextUri / contextNamestringアーティストと、再生元（プレイリストなど）
playing / bufferingboolean再生中・読み込み中
pos / durnumber（ミリ秒）送った時点の位置（経過時間を足した値）と長さ
shuffle / repeatboolean / 0〜2シャッフル・リピート
likedbooleanお気に入りの曲か（曲が変わったときに一度だけ調べる）
device / deviceTypestringほかの機器で再生中ならその名前と種類（このスマホなら空）

送るのは、曲・機器・お気に入り・再生中か・シャッフル・リピート・読み込み中・位置（5 秒単位）のどれかが変わったときだけです。

5.4 呼び出し（Bridge.call）

suspend fun call(method: String, args: JSONObject = JSONObject()): Any?
// 1. 連番の id を振り、結果を待つ CompletableDeferred を登録
// 2. webView.evaluateJavascript("__mb.call(id, 'method', args)")
// 3. bres が届いたら ok なら value を返し、だめなら例外
// 4. 時間切れは bridge.timeout としてデバッグログに残す

5.6 Web Player の部品の取り出し

platform() は React のルートからたどって getRegistry() を持つ値を探します。service(name) はその登録簿から説明（description）が name の部品を取り出し、名前とキーの対応を覚えておきます（毎秒何十回も呼ぶため）。

部品の名前用途
PlayerAPI再生の操作・状態・キュー
PlayerSDK音声要素・音質・先読み（harmony の streamer）
LibraryAPI / RootlistAPIライブラリ・プレイリストとフォルダ
AdManagers広告マネージャー（停止する）
AuthorizationAPIログイン情報

5.7 polyfill.js の中身

  • MediaSession の代用：Android WebView に無い navigator.mediaSession と MediaMetadata を補う。無いと Web Player の再生処理が止まる
  • アプリとの窓口：window.__native（send・setPlaying・getSetting・setSetting・relay）
  • Connect：connect-state の通信から自分の機器 ID とクラスタ（機器の一覧・再生中の機器）を覚え、window.__mConnect（get・onChange・transfer）で使えるようにする。再生コマンドは ConnectRelay で端末から送り直す
