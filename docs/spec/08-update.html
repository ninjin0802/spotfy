8. アプリ内アップデート

GitHub Releases の最新版を確かめ、ダウンロードしてインストーラーに渡すまで。

8.1 状態

状態設定の行の表示
Idle押すと新しい版を確認します
Checking確認中…
UpToDate最新の版です
Available新しい版 X があります（お知らせのダイアログも出る）
Downloadingダウンロード中… N%
Ready押すと X をインストールします
Failed確認できませんでした／ダウンロードに失敗しました

8.2 確認のタイミング

  • 起動して Web Player の準備ができたとき（checkIfDue）。前回の確認から 6 時間たっていなければ何もしない
  • 設定の「アップデート」を押したとき（check(manual = true)）
  • 起動時の確認では、「あとで」にした版はもう出さない（手動の確認では出す）

8.3 最新版の調べ方

  1. GitHub API：GET https://api.github.com/repos/ninjin0802/spotfy/releases/latest。tag_name・body（リリースノート）・.apk の資産の URL と大きさを取る
  2. API に断られたとき（IP ごとに 1 時間 60 回まで。VPN などで 403 になる）：https://github.com/ninjin0802/spotfy/releases/latest の転送先（/tag/vX.Y.Z）から版を取り、APK は releases/download/vX.Y.Z/spotfy-X.Y.Z.apk、リリースノートはそのタグの CHANGELOG.md の節から取る
  3. 版の比較は数字ごと（2.10.0 > 2.9.3）

8.4 ダウンロードとインストール

  • 保存先は cacheDir/updates/spotfy.apk。まず .part に書き、大きさが合っていれば名前を変える
  • 進み具合は 1% ごとに知らせる。ダウンロードは画面を閉じても続ける（Updater 自身のコルーチン）
  • 転送（リダイレクト）は自分で追い、https 以外への転送は拒否する（最大 5 回）
  • 終わったら FileProvider（${applicationId}.updates）の URI で ACTION_VIEW を開く
  • 「この提供元のアプリを許可」がまだなら、先にその設定画面を開く
  • 最新の版だと分かったら、残っている APK を消す

8.5 安全性

  • Android は同じ署名の APK でしか上書きを許さないため、ほかの人が作った APK に置き換わることはない
  • 通信は https だけ。トークンなどの秘密の情報は使わない

8.6 記録

イベント意味
update.api.failedAPI に断られ、リリースページから調べ直した
update.check.failed確認に失敗した
